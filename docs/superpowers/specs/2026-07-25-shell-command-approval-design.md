# Shell 命令分级审批设计

## 背景

当前 `ShellTool` 只允许固定命令集合，并且在进入人工确认之前拒绝其他
命令。该策略能够限制执行面，但会阻止 `uv`、`pytest`、`python`、包管理器
以及大量正常的 Git 操作。与此同时，当前允许的命令仍然全部逐次确认，
没有利用其中可证明只读的调用降低交互成本。

本设计将 Shell 执行改为分级审批：

- 参数安全且仅访问当前 workspace 的内置只读命令自动执行；
- 其他有效命令逐次请求人工确认；
- 用户可以在确认时将本次完整命令持久授权给当前 workspace；
- 参数结构无效的调用直接拒绝。

## 目标

- 允许任意可执行文件、相对或绝对程序路径，以及 `python`、
  `powershell`、`cmd` 等解释器在人工确认后运行。
- 对一小组能够证明只读的命令免除确认。
- 支持“仅本次允许”和“在当前 workspace 中始终允许”。
- 长期授权采用完整最终 argv 的精确匹配，不引入命令前缀、通配符或
  模糊规则。
- 保留当前参数数组执行、`shell=False`、净化环境、超时限制和输出限制。
- 授权状态只保存在当前 workspace，不进入 Git、日志或 trace。

## 非目标

- 不提供命令模式、正则表达式、参数前缀或可执行文件级别的宽泛授权。
- 不为 Shell 之外的工具增加永久授权。
- 不增加授权管理 CLI；首版通过编辑或删除授权文件撤销授权。
- 不提供操作系统级沙箱或权限降级。
- 不迁移现有 `.cdy-agent/config.yaml` 配置格式。

## 方案选择

### 仅按命令名分类

只读命令名自动执行，其他命令确认。该方案简单，但无法区分
`sort input` 与 `sort -o output`，也无法阻止 `rg --pre` 等委托执行。

### 按完整 argv 分类

校验并规范化完整 argv，再返回自动执行、人工确认或拒绝。该方案能保留
安全边界，同时支持任意命令经用户批准后执行。本设计采用该方案。

### 通用风险评分

根据命令、参数、路径和关键字计算风险等级。该方案规则不透明、误判难以
解释，并且超出当前项目需要。

## 架构

### `ShellExecutionPolicy`

Shell 执行策略根据已校验、最终实际执行的 argv 返回三种结果：

- `AUTO_APPROVE`：内置只读命令的安全参数组合，或命中当前 workspace
  的持久授权。
- `REQUIRE_CONFIRMATION`：其他所有结构有效的命令。
- `REJECT`：argv 或超时等工具参数结构无效。

策略分类是纯判断逻辑，不执行进程，也不直接与终端交互。

### `ShellApprovalStore`

独立存储组件管理：

```text
<workspace>/.cdy-agent/shell-approvals.json
```

文件采用版本化 JSON：

```json
{
  "version": 1,
  "allowed_commands": [
    ["uv", "run", "pytest"],
    ["python", "-m", "pytest", "tests/test_cli.py"]
  ]
}
```

每个命令必须是非空字符串数组。未知字段、未知版本、空命令、非字符串
参数或其他无效结构均视为存储错误。读取不创建目录或文件。

存储组件在每次匹配前重新读取文件，因此用户手动修改或删除授权后立即
生效。新增授权时重新读取当前内容、去重、写入同目录临时文件，并通过
`os.replace` 原子替换目标文件。`.cdy-agent` 和目标文件必须遵循项目已有
的 workspace containment、符号链接和普通文件检查规则。

### 动态确认协议

当前工具协议使用静态 `requires_confirmation` 布尔值，无法根据 Shell
参数决定是否确认。注册表需要支持工具按本次参数返回确认要求，同时保持
现有工具的静态行为不变。

确认回调的结果需要区分：

- 拒绝；
- 仅本次允许；
- 持久允许。

只有声明支持持久授权的 Shell 工具能够收到“持久允许”。注册表在该结果
下先调用 Shell 的授权保存逻辑；只有保存成功才执行命令。其他工具继续
使用现有的逐次确认语义。

## 命令身份与匹配

授权保存和匹配的键是最终实际传给 `subprocess.run` 的 argv：

- 逐元素精确匹配；
- 参数顺序必须一致；
- 区分大小写；
- 不解析或重组命令字符串；
- 不使用前缀或通配符；
- 不因可执行文件名相同而授权其他参数。

确认提示也展示该最终 argv，确保用户看到、保存和执行的是同一命令。
授权文件位于单个 workspace 内，执行 cwd 固定为该 workspace，因此授权
记录不重复保存 cwd。

例如，允许：

```text
["python", "script.py"]
```

不会允许：

```text
["python", "-c", "code"]
["python", "script.py", "--delete"]
["Python", "script.py"]
```

相对路径指向的程序或脚本内容可能在未来发生变化。持久授权代表用户信任
该 workspace 中相同最终 argv 的后续执行，而不是信任某个文件哈希。

## 内置只读命令

只读自动执行集合为：

- `pwd`
- `ls`
- `rg`
- `grep`
- `head`
- `tail`
- `wc`
- `sort`
- `uniq`
- `git status`
- `git diff`

命令名必须精确匹配。绝对路径、包含路径分隔符的命令以及同名包装脚本不
属于内置只读命令，但可以进入人工确认。

自动执行不仅检查命令名，还必须检查完整参数和输入路径：

- 所有输入路径解析后必须位于当前 workspace；
- 指向 workspace 外部的绝对路径、`..` 路径或符号链接降级为人工确认；
- 无法可靠解析的参数组合降级为人工确认；
- 未知选项降级为人工确认，而不是假定只读；
- 危险参数降级为人工确认，不再像现有白名单那样硬拒绝。

命令特定规则至少包括：

- `rg` 强制加入 `--no-config`，`--pre` 及其他委托执行形式需要确认；
- `sort -o`、`sort --output`、`sort --compress-program` 及其他写入或
  委托执行形式需要确认；
- `uniq` 的输出文件操作数需要确认；
- `git status` 和 `git diff` 强制禁用可选锁、fsmonitor、外部 diff 和
  textconv；
- `git diff --output` 及其他写入形式需要确认。

策略实现应采用命令特定的保守参数解析器。解析器只需要识别明确支持的
只读形式；不能证明安全的调用统一进入确认路径。

## 执行流程

1. `ToolRegistry` 解码工具参数。
2. `ShellTool.preflight` 校验 argv 和超时。
3. Shell 计算最终实际执行 argv。
4. 只读分类器判断是否为 workspace 内的安全只读调用。
5. 若不是安全只读调用，审批存储重新加载 JSON 并精确匹配最终 argv。
6. 安全只读或命中授权的命令直接执行。
7. 其他命令创建支持持久授权的确认请求。
8. 用户拒绝时返回 `approval_denied`。
9. 用户选择仅本次允许时直接进入执行。
10. 用户选择持久允许时，注册表先保存授权；保存失败则不执行。
11. Shell 在执行前再次校验当前参数，并使用最终 argv 调用 runner。

## CLI 交互

Shell 确认提示展示最终 argv、workspace 和当前用户权限：

```text
Run command ['uv', 'run', 'pytest'] in workspace D:\project
with current user permissions.
[y] once / [a] always / [N] deny:
```

输入规则：

- `y` 或 `yes`：仅本次允许；
- `a` 或 `always`：成功保存后允许本次及后续精确匹配；
- 空输入、其他输入、EOF、Ctrl+C 或 Typer 中断：拒绝。

其他工具继续显示现有 `[y/N]` 提示，只接受 `y` 或 `yes`。

## 失败处理

- 参数结构无效：确认前返回 `invalid_arguments`。
- 命令不存在：返回现有 `execution_error`。
- 超时：返回现有 `command_timeout`。
- 非零退出：返回现有 `command_failed`。
- 审批文件不存在：视为空授权集合，不创建文件。
- 审批文件损坏、版本不支持、越界、不是普通文件或读取失败：不使用任何
  持久授权，命令回退到逐次确认。
- 在审批存储不可用时选择“仅本次允许”：可以执行。
- 在审批存储不可用时选择“持久允许”：返回结构化审批存储错误且不执行。
- 原子写入失败：保留原文件，清理可清理的临时文件，命令不执行。

并发新增采用写入前重新读取、合并和原子替换，不引入跨平台文件锁。两个
进程极端竞态时可能丢失一条刚新增授权，结果只是后续多一次确认，不会
扩大权限或产生半写文件。

## 安全边界

- 所有命令继续使用参数数组和 `shell=False`；Shell 元字符只是普通参数。
- runner 固定使用解析后的 workspace 作为 cwd。
- 保留净化环境、最长执行时间和 stdout/stderr 字节上限。
- 持久授权允许解释器和路径程序，因此用户选择 `always` 时明确是在当前
  用户权限下信任相同 argv 的未来执行。
- 只读自动执行仅适用于 workspace 内输入。workspace 外读取必须得到确认。
- 授权内容不得写入结构化日志、trace 或模型响应缓存。
- `.cdy-agent/` 已被 Git 忽略，审批状态不会进入版本控制。

## 测试

测试全部离线并注入 runner 或文件边界，不执行真实外部命令。

### 策略分类

- 每个内置只读命令的安全参数组合返回 `AUTO_APPROVE`。
- 写入、委托执行、未知选项和无法解析参数返回
  `REQUIRE_CONFIRMATION`。
- 非内置命令、解释器、相对路径和绝对路径程序需要确认。
- workspace 外路径和越界符号链接需要确认。
- argv、超时和参数对象无效时拒绝。

### 审批存储

- 文件缺失返回空集合且不创建 `.cdy-agent`。
- 完整 argv 命中后自动执行。
- 大小写、顺序、参数数量或内容不同均不匹配。
- 版本、schema、JSON、符号链接和普通文件校验失败。
- 重复授权去重。
- 原子写入成功、替换失败和临时文件清理。
- 读取异常不会产生自动授权。

### 注册表与 CLI

- 自动命令不调用确认回调。
- `y` 仅执行一次，后续仍确认。
- `a` 先持久化再执行，后续不确认。
- `n`、空输入、无效输入、EOF 和中断拒绝。
- 持久化失败时 runner 未被调用。
- 不支持持久授权的工具保持原有 `[y/N]` 行为。
- 确认文案只显示一次，并包含最终 argv、workspace 和当前用户权限。

### 回归验证

- 运行完整 `uv run pytest`。
- 运行 `uv run cdy-agent --help`。
- 运行 `uv run cdy-agent ask --help`。
- 运行 `uv build`。
